# Version 2 popup: the 18 screen states

**These pictures were made with the pretend model, not the real one.** The popup code is the real code. The model is the fake in `src/offscreen/mock-engine.js`: nothing is downloaded, the "download" takes about one second, the answers are fixed text, and the sizes and times shown (for example "about 664 MB" and "0.2 s") are the fake's numbers. They say nothing about how the real Llama 3.2 1B or SmolLM2 360M performs.

## How the pictures were made

- Script: `scripts/shoot-ui-states.mjs` (run from the project folder with `node scripts/shoot-ui-states.mjs`; add state names such as `ui-04` to shoot only some). It runs hidden: headless Chromium through the same harness as the browser tests, with no visible window.
- Each picture is the popup page only, at 2x pixel density (760 px wide), cropped to the popup's content. There is no window frame and no desktop.
- Settings used are written as `engineMode`, `mockDelayMs`, `chunkChars`, and whether the pretend model counts as downloaded (`cached`). Defaults are `engineMode: mock`, `mockDelayMs: 50`, `chunkChars: 6000`, `cached: no` unless a row says otherwise.
- Three states needed special handling, because the pretend model passes through them too fast to photograph:
  - ui-02 and ui-04: the popup's script is paused the moment that text appears on screen, the picture is taken while the screen is frozen, and the popup then carries on. Nothing else about the popup is changed.
  - ui-03: the pretend model never reports "Loading the model into the graphics card", so this one job record is written into the extension's session storage, in the same shape the service worker writes it. The popup draws it the same way it would for a real load.
  - ui-05 and ui-06: the pretend model is slowed to 2 s per answer, so each stage stays on screen long enough to shoot.

## Things the pictures show

- When the small model took over (ui-12) the popup now says so with a notice above the summary. This was added after the first set of pictures showed no message at all; ui-12 and ui-13 were re-shot afterwards. The job record's `notice` field is still always empty: the notice is worked out in the popup from the stats.
- In ui-13 the model line is refreshed once when the job ends, so it names the small model that the failed job saved as the choice.
- ui-16 has no title line because Chrome gave the `chrome://version` tab an empty title in this run.
- ui-04's progress bar is animated, so the still shows it as a plain grey line.
- The sizes "about 664 MB" and "about 300 MB" and the times "0.2 s" and "2.2 s" are the pretend model's numbers, not measurements.
