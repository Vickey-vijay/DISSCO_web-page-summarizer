# Development log

Real problems met while building this project, written as they happen. Each entry: date, what broke or was hard, symptom or error, root cause, fix, what was learned. Nothing is recorded here that did not actually happen.

| Date | Area | Symptom | Root cause | Fix | Lesson |
|---|---|---|---|---|---|
| 2026-10-20 | run.bat / testing (M0) | Launching the installed Google Chrome 155 with `--load-extension=<folder>` through Playwright showed no extension service worker within 8 s. Playwright's bundled Chromium 156 with the same flags loaded it at once. | The Chromium team removed the `--load-extension` flag from branded Chrome builds in Chrome 137 (announced April 2025). Chromium and Chrome for Testing keep it. Confirmed by `tests/e2e/chrome-flag-check.mjs`. | `run.bat` cannot launch Chrome with the extension pre-loaded. It opens `chrome://extensions` and prints the exact "Load unpacked" steps. Automated tests run on Playwright's Chromium. | Check what a browser flag really does on the target machine before building a launcher around it. Tests on Chromium do not prove the install path in branded Chrome, so a manual Load-unpacked smoke test is still needed. |
| 2026-10-20 | unit tests (M3/M4) | `node --test tests/unit` failed with `Cannot find module ...\tests\unit`. | Node 22 on Windows treats the argument as a file path, not a folder to scan. | Changed the npm scripts to use a glob: `node --test "tests/unit/*.test.js"`. | Use globs for test discovery on Windows. |
| 2026-10-20 | Gemini engine tests (M4) | After a timeout test, four tests showed as "cancelled" instead of passing or failing. Several others failed with an empty-answer error. | Two causes. (1) `AbortSignal.timeout()` timers do not keep Node's event loop alive, so a hanging fake request let the test runner exit early. (2) The test helper replayed one `Response` object for several calls, but a response body can only be read once. | (1) Replaced `AbortSignal.timeout` in the engine with its own `setTimeout` + `AbortController`, cleared in a `finally` block (also tidier in the browser). (2) The fake `fetch` now hands out `response.clone()`. | A flaky-looking test is often a test-harness bug; check what the fake object allows before changing product code. The engine change was still worth keeping. |
| 2026-10-20 | cloud model choice (M4) | `gemini-3.8-flash` answered a 2-word test prompt in 9.4 s, and a real 7,000-character summary request took 11.4 to 12.6 s in three runs. One request also returned HTTP 503 "high demand". | The model "thinks" by default: the usage data showed about 1,600 thinking tokens against about 250 output tokens. With a 25 s request timeout and several chunks per long page, that is too close to the limit. | Benchmarked six model / thinking settings with `scripts/model-bench.mjs` (results in `docs/test-runs/model-bench.json`). Kept `gemini-3.8-flash` and added `thinkingLevel: low`, which cut a typical request to about 3.9 s (one run in three was 12.5 s). `thinkingLevel: minimal` is rejected by this model with HTTP 400. Faster alternatives were `gemini-3.5-flash-lite` (1.6 to 2.0 s) and `gemini-2.5-flash` with thinking off (2.4 to 2.7 s). The 503 is handled by the retry logic. | Measure latency on the real task before fixing a model and a timeout. The cheapest speed-up was a request setting, not a different model. Summary quality of the faster models was not compared; that is a limitation. |
| 2026-10-20 | setup.bat (M7) | First real run of `setup.bat` stopped at step 2 with `116 was unexpected at this time.` | The Chrome major version was stored in a variable and compared (`if %CHROME_MAJOR% lss 116`) inside the same parenthesised block that set it. cmd expands `%var%` when it reads the whole block, so the variable was still empty at that point and the line became invalid. | Moved the version checks into their own subroutines with `goto` instead of an `if (...)` block. | In batch files a variable set inside a `( ... )` block cannot be read in that same block. Run the script for real; reading it looked fine. |
| 2026-10-20 | setup.bat (M7) | After a scripted edit, setup.bat failed with `The system cannot find the batch label specified - check_chrome_version`. | The edit searched for the text `:find_chrome` to insert a new subroutine before it, but the first match was the `call :find_chrome` line in the main flow, so the subroutine was pasted into the middle of a line. | Rewrote the whole file cleanly and converted it to CRLF. The bat test script (`tests/bat/test-bat-scripts.ps1`) caught it at once. | Do not patch batch files by text search; rewrite them whole and list their labels afterwards. |
| 2026-10-20 | bat tests (M7) | The test script reported `'run.bat' is not recognized as an internal or external command` even though the file was in the current folder. Later, a test hung. | On this machine cmd does not search the current folder for commands (`.\` is required). The hang came from the stand-in "Chrome" batch file being opened by `start` in a `cmd /K` window that never closed, so the output pipe stayed open. | Tests call `.\setup.bat` and `.\run.bat`, and the stub ends with `exit`. | Test harnesses need to clean up the processes they start. The clipboard step of run.bat is not auto-tested because the test must not read or overwrite the user's clipboard. |
| 2026-10-20 | popup and service worker (M8, bug B1) | Browser test T19: pressing Summarize after the tab moved to another page, while the old page's summary was still running, did nothing. The popup stayed blank. | The service worker allows one job per tab and answered `already_running`. The popup ignored that answer, and it also hides any job whose URL differs from the page, so the running job was invisible. | Each job now has an id. If the tab has moved to a different page, the old job is aborted and replaced; writes from a replaced job are dropped. The popup now reads the service worker's reply and shows the current job or an error. | Every refusal has to reach the user. A silent "no" looks like a broken button. |
| 2026-10-20 | popup (M8, bug B2) | Browser test T20: an open popup kept showing "Summarizing..." with a disabled button after the service worker had died and the job was older than 3 minutes. | The popup only checked "is this job stale" when the popup started or when storage changed. A dead worker writes nothing, so nothing triggered the check. | The popup re-renders its last job every 5 seconds, so a job past the 3-minute limit turns into "interrupted". | A timeout that is only checked on events never fires when the thing it guards has stopped sending events. |
| 2026-10-20 | extractor (M8, bug B3) | Browser test T21: on a page with a table the model received "QuarterRevenueMargin" and "Q14.5M12%". The summary still looked normal, so nothing on screen showed the damage. | The text walker treated `tr` as a block but not `td` or `th`, so cells in minified HTML had no separator. | Cells are now joined with " | " and each row is one line ("Q1 \| 4.5M \| 12%"). My first fix made every row a separate paragraph, which T21 also caught. | Silent data corruption is worse than a visible error. Test with the markup real sites produce (no whitespace between cells). |
| 2026-10-20 | service worker (M8, bug B4) | Browser test T22: after a tab was closed mid-job, a record with the full summary was still in `chrome.storage.session`. | The tab-removed handler deleted the record, but the job kept running and its queued writes re-created it from `{...current, ...patch}`. | Closed tabs are remembered, their job is aborted, and a write is only applied if the stored record still has the writer's job id. | A cleanup handler cannot win against work that is still running; stop the work as well. |
| 2026-10-20 | review of test findings (M8) | The test agent's notes listed risks that had no failing test: no limit on how many parts one page may need, a possible double start if two popups click at once, and every HTTP 403 being reported as "your key was rejected". | Missing guards rather than defects. | Added a page-length limit (`maxChunks`, default 30, code TOO_LONG, test T23), a per-tab "starting" lock, and a 403 about the caller's location is now a service problem. The options page Save button no longer squeezes the key field. | A free-tier key makes "one huge page" a real cost risk, so a limit is part of the error handling, not an extra feature. |
| 2026-10-20 | design change after owner feedback (M8) | The project owner watched the test run and said the extension should open in a popup (or a side panel), not in a new tab; that V1 should stay simple; that the UI looked AI-made; and that tests should be hidden and use cheap models. | The test harness opened the popup page as a browser tab (a test cannot click the toolbar icon) and the Options page opens as a tab, so the product looked like it opened tabs. The first UI used the common blue, rounded-card look. | The key can now be pasted inside the popup (Key box), so nothing opens in a new tab. The harness opens the popup as a small popup window. The UI and icon were redrawn in a printed-page style (paper, ink, one red accent, serif summary text, numbered points). Browser tests run hidden by default (HEADED=1 to watch). The default model is the cheap gemini-3.5-flash-lite. V1 documents are to stay in plain language, with AI internals left for V2. | Watching the test run exposed a mismatch between what the harness showed and what the product does. Fix the harness so it shows the truth. |
| 2026-10-20 | model choice and quota (live runs, after M7) | The first live runs with gemini-3.8-flash summarized L01 to L03, then L04 to L07 failed with HTTP 429: "Quota exceeded ... limit: 20" and a retry time of about 7 hours. The probe in quota-probe.json then showed gemini-3.5-flash-lite answered 16 requests before the service named a limit of 15 a minute; gemini-2.5-flash-lite named 10, gemini-2.5-flash named 5, and gemini-3.1-flash-lite returned HTTP 503 "high demand". | The large model has a small daily free allowance (20 requests named by the service), and the smaller models have a per-minute allowance. The probe sent requests about 0.7 s apart. The reason 16 succeeded when the limit named was 15 is not explained by the repository and is recorded as an open question. | Default changed to gemini-3.5-flash-lite. A wait longer than 25 s is now reported at once as QUOTA_EXHAUSTED, with the time to wait, and the popup offers the Key box so the user can change the key. Live runs were repeated with the new default (L01 to L07 summarized). | Read the limit the service names in its error, not only the documentation, and test the exact model you will demonstrate before the viva. |
| 2026-10-20 | prompt tests (M4) | A prompt test failed: the page text appeared to be before the "start" marker. | The instruction line also names both markers, so `indexOf` found the first mention, not the real one. | Test now compares with `lastIndexOf`. Prompt unchanged. | Markers repeated in instructions make position checks ambiguous. |
