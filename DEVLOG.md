| 2026-10-20 | run.bat / testing (M0) | Launching the installed Google Chrome 155 with `--load-extension=<folder>` through Playwright showed no extension service worker within 8 s. Playwright's bundled Chromium 156 with the same flags loaded it at once. | The Chromium team removed the `--load-extension` flag from branded Chrome builds in Chrome 137 (announced April 2025). | 2026-10-20 | unit tests (M3/M4) | `node --test tests/unit` failed with `Cannot find module ...\tests\unit`. | Node 22 on Windows treats the argument as a file path, not a folder to scan. | Changed the npm scripts to use a glob: `node --test "tests/unit/*.test.js"`. | Use globs for test discovery on Windows. |
| 2026-10-20 | Gemini engine tests (M4) | After a timeout test, four tests showed as "cancelled" instead of passing or failing. Several others failed with an empty-answer error. | Two causes. (1) `AbortSignal.timeout()` timers do not keep Node's event loop alive, so a hanging fake request let the test runner exit early. (2) The test helper replayed one `Response` object for several calls, but a response body can only be read once. | (1) Replaced `AbortSignal.timeout` in the engine with its own `setTimeout` + `AbortController`, cleared in a `finally` block (also tidier in the browser). (2) The fake `fetch` now hands out `response.clone()`. | A flaky-looking test is often a test-harness bug; check what the fake object allows before changing product code. The engine change was still worth keeping. |
| 2026-10-20 | cloud model choice (M4) | `gemini-3.8-flash` answered a 2-word test prompt in 9.4 s, and a real 7,000-character summary request took 11.4 to 12.6 s in three runs. One request also returned HTTP 503 "high demand". | The model "thinks" by default: the usage data showed about 1,600 thinking tokens against about 250 output tokens. With a 25 s request timeout and several chunks per long page, that is too close to the limit. | Benchmarked model and thinking settings with `scripts/model-bench.mjs`; four settings have saved results in `docs/test-runs/model-bench.json`. The two others mentioned in an earlier note of this log were not saved, so they are not claimed here. Kept `gemini-3.8-flash` and added `thinkingLevel: low`, which cut a typical request to about 3.9 s (one run in three was 12.5 s). `thinkingLevel: minimal` is rejected by this model with HTTP 400. Faster alternatives were `gemini-3.5-flash-lite` (1.6 to 2.0 s) and `gemini-2.5-flash` with thinking off (2.4 to 2.7 s). The 503 is handled by the retry logic. | Measure latency on the real task before fixing a model and a timeout. The cheapest speed-up was a request setting, not a different model. Summary quality of the faster models was not compared; that is a limitation. |
| 2026-10-20 | setup.bat (M7) | First real run of `setup.bat` stopped at step 2 with `116 was unexpected at this time.` | The Chrome major version was stored in a variable and compared (`if %CHROME_MAJOR% lss 116`) inside the same parenthesised block that set it. cmd expands `%var%` when it reads the whole block, so the variable was still empty at that point and the line became invalid. | Moved the version checks into their own subroutines with `goto` instead of an `if (...)` block. | In batch files a variable set inside a `( ... )` block cannot be read in that same block. Run the script for real; reading it looked fine. |
| 2026-10-20 | setup.bat (M7) | After a scripted edit, setup.bat failed with `The system cannot find the batch label specified - check_chrome_version`. | The edit searched for the text `:find_chrome` to insert a new subroutine before it, but the first match was the `call :find_chrome` line in the main flow, so the subroutine was pasted into the middle of a line. | Rewrote the whole file cleanly and converted it to CRLF. The bat test script (`tests/bat/test-bat-scripts.ps1`) caught it at once. | Do not patch batch files by text search; rewrite them whole and list their labels afterwards. |
| 2026-10-20 | bat tests (M7) | The test script reported `'run.bat' is not recognized as an internal or external command` even though the file was in the current folder. Later, a test hung. | On this machine cmd does not search the current folder for commands (`.\` is required). The hang came from the stand-in "Chrome" batch file being opened by `start` in a `cmd /K` window that never closed, so the output pipe stayed open. | Tests call `.\setup.bat` and `.\run.bat`, and the stub ends with `exit`. | Test harnesses need to clean up the processes they start. | 2026-10-20 | popup and service worker (M8, bug B1) | Browser test T19: pressing Summarize after the tab moved to another page, while the old page's summary was still running, did nothing. The popup stayed blank. | The service worker allows one job per tab and answered `already_running`. The popup ignored that answer, and it also hides any job whose URL differs from the page, so the running job was invisible. | Each job now has an id. | 2026-10-20 | popup (M8, bug B2) | Browser test T20: an open popup kept showing "Summarizing..." with a disabled button after the service worker had died and the job was older than 3 minutes. | The popup only checked "is this job stale" when the popup started or when storage changed. A dead worker writes nothing, so nothing triggered the check. | The popup re-renders its last job every 5 seconds, so a job past the 3-minute limit turns into "interrupted". | A timeout that is only checked on events never fires when the thing it guards has stopped sending events. |
| 2026-10-20 | extractor (M8, bug B3) | Browser test T21: on a page with a table the model received "QuarterRevenueMargin" and "Q14.5M12%". The summary still looked normal, so nothing on screen showed the damage. | The text walker treated `tr` as a block but not `td` or `th`, so cells in minified HTML had no separator. | Cells are now joined with " | " and each row is one line ("Q1 \| 4.5M \| 12%"). My first fix made every row a separate paragraph, which T21 also caught. | Silent data corruption is worse than a visible error. | 2026-10-20 | service worker (M8, bug B4) | Browser test T22: after a tab was closed mid-job, a record with the full summary was still in `chrome.storage.session`. | The tab-removed handler deleted the record, but the job kept running and its queued writes re-created it from `{...current, ...patch}`. | Closed tabs are remembered, their job is aborted, and a write is only applied if the stored record still has the writer's job id. | A cleanup handler cannot win against work that is still running; stop the work as well. |
